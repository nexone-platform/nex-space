## 1. ทำไมต้อง 47 tiles? (blob 8-neighbour)

ผนังต้องต่อกันเนียนไม่ว่ารูปทรงห้องแบบไหน — มุมนอก มุมใน สามแยก สี่แยก ปลายผนัง ฯลฯ
**47 คือจำนวน "รูปแบบผนังที่ต่างกันจริง" ทั้งหมด** เมื่อพิจารณาเพื่อนบ้าน 8 ทิศ โดยมีกฎว่า:

- เพื่อนบ้าน **แนวตรง (N/E/S/W)** — นับเสมอ
- เพื่อนบ้าน **แนวทแยง (NE/SE/SW/NW)** — นับเฉพาะเมื่อแนวตรงสองด้านที่ขนาบมุมนั้น "เป็นผนังทั้งคู่" (ไม่งั้นมุมนั้นเปิดอยู่แล้ว ทแยงไม่มีผล)

นับตามกฎนี้ได้ **47 เคสพอดี** (พิสูจน์: 1 + 4 + 2 + 8 + 16 + 16 = 47 — ดูตาราง §4)

> ผลลัพธ์: วาดแค่ 47 ช่อง แต่ประกอบผนังได้ **ทุกรูปทรง** ที่เป็นไปได้ ไม่มีรอยต่อแหว่ง

## 2. วิธีอ่านภาพอ้างอิง (`wall-blob-47.svg`)

แต่ละการ์ดในภาพ = 1 tile ที่ต้องวาด ประกอบด้วย:

| องค์ประกอบ | ความหมาย |
|-----------|----------|
| **`#0`–`#46`** (มุมซ้ายบน) | **index** ของ tile = ลำดับตำแหน่งใน atlas (ดู §3) |
| **ตาราง 3×3 เล็ก** (มุมขวาบน) | ตัวช่วยบอกเพื่อนบ้าน: ช่องกลาง 🟩 = tile นี้, ช่องเทา = ด้านที่ "มีผนังต่อ", ช่องครีม = เปิด/พื้น |
| **รูปทรงผนังตรงกลาง** | สเก็ตช์รูปผนังที่ต้องได้ — ด้านที่มีเพื่อนบ้าน = ผนังชนขอบเต็ม, ด้านเปิด = ร่นเข้า (เห็นผิวผนังด้านนอก), มุมในเว้าเป็น notch |
| **โค้ดสีเขียว** (ล่าง) | รหัสการเชื่อม เช่น `NE` = ต่อขึ้น+ขวา, `+NE` = มุมทแยง NE เป็นผนังด้วย |

**อ่านตาราง 3×3 = พิมพ์เขียวของ tile:** วาดผนังให้ "เต็มขอบ" ทางด้านที่ช่องเทาติดกัน และ "เก็บขอบ/โชว์ผิว" ทางด้านช่องครีม เท่านี้ผนังจะต่อกันเนียนเองเมื่อ engine เลือก tile ถูกช่อง

## 3. สเปกไฟล์ atlas

| พารามิเตอร์ | ค่า |
|------------|-----|
| Logical tile | **32 × 32 px** |
| วาดจริง (art) | **@2x = 64 × 64 px** ต่อ tile |
| Grid ของ sheet | **8 คอลัมน์** × 6 แถว (47 tiles + 1 ช่องว่าง) |
| ตำแหน่ง tile index `k` | `col = k mod 8`, `row = k div 8` |
| พิกัดพิกเซล @1x | `(col×32, row×32)` |
| พิกัดพิกเซล @2x | `(col×64, row×64)` |
| ไฟล์ผลลัพธ์ | `walls-<theme>.png` + `walls-<theme>.tsx` |
| พื้นหลัง | โปร่งใส (alpha) |

> ลำดับ index ในภาพ = ลำดับใน atlas เป๊ะ ๆ ทีมศิลป์วาดช่องไหน = วางตรงตำแหน่งนั้นใน PNG
> พิกัดครบทั้ง 47 อยู่ใน `wall-blob-47.atlas.json` (ฟิลด์ `px_2x`) ดึงเข้าโค้ด/สคริปต์ได้เลย

## 4. หมวดของ tile (จัดกลุ่มตาม index)

| Index | จำนวน | หมวด | ลักษณะที่ต้องวาด |
|-------|-------|------|------------------|
| **#0** | 1 | **เสาเดี่ยว (isolated)** | บล็อกกลาง ๆ ไม่ต่อด้านไหน (เสา/pillar) |
| **#1–#4** | 4 | **ปลายผนัง (end cap)** | ต่อด้านเดียว — ปลายผนังโผล่ทาง N/E/S/W |
| **#5,#6** | 2 | **มุม N-E** | #5 มุมนอก (โค้ง/เก็บมุม), #6 มุมทึบ (ทแยงเต็ม) |
| **#7** | 1 | **แนวตั้งตรง (N-S)** | ผนังแนวดิ่งผ่านกลาง |
| **#8,#9** | 2 | **มุม N-W** | นอก / ทึบ |
| **#10,#11** | 2 | **มุม E-S** | นอก / ทึบ |
| **#12** | 1 | **แนวนอนตรง (E-W)** | ผนังแนวนอนผ่านกลาง |
| **#13,#14** | 2 | **มุม S-W** | นอก / ทึบ |
| **#15–#18** | 4 | **สามแยก N-E-S** (T หันขวา) | 4 แบบตามมุมในซ้าย/ขวาเว้าหรือทึบ |
| **#19–#22** | 4 | **สามแยก N-E-W** (T หันขึ้น) | 4 แบบ |
| **#23–#26** | 4 | **สามแยก N-S-W** (T หันซ้าย) | 4 แบบ |
| **#27–#30** | 4 | **สามแยก E-S-W** (T หันลง) | 4 แบบ |
| **#31–#46** | 16 | **สี่แยก / กลางผนังหนา (N-E-S-W)** | 16 แบบ ตามมุมใน 4 มุมว่าเว้าหรือทึบ (ตั้งแต่มุมในครบ 4 → พื้นที่ผนังทึบเต็ม) |

**หลักการวาดร่วมทุกหมวด:**
1. ด้านที่ "ต่อ" ผนังต้องชนขอบ tile เป๊ะ ๆ (pixel เดียวกันทุก tile) เพื่อให้ต่อกันเนียน — **สำคัญที่สุด**
2. ด้านเปิด ร่นเข้าเท่ากันทุก tile (แนะนำ 5–6 px @2x) โชว์ความหนา/ผิวผนัง
3. มุมใน (notch) ขนาดเท่ากันทุกที่
4. แสงทิศเดียว (บน-ซ้าย) → cap ด้านบนสว่าง, ด้านล่างมีเงาบาง

## 5. การทำผนัง 2.5D (ความสูง/หน้าผนัง)

มุมมอง top-down 2.5D ผนังควรมี "ความสูง" ให้เห็นด้านหน้า มี 2 ทางเลือก:

### ทางเลือก A — Baked face (แนะนำสำหรับ MVP) ✅
วาด "หน้าผนัง" สูงประมาณ 8–12 px @2x ไว้ **ในตัว tile เลย** ที่ขอบล่าง (เฉพาะเคสที่ด้านล่างเปิด)
- ข้อดี: single layer, ยังคง 47 tiles, ง่ายสุด
- ข้อเสีย: ความสูงคงที่ ตัวละครเดินหลังผนังบังได้จำกัด

### ทางเลือก B — Separate face layer (fidelity สูง)
Blob 47 = "top/cap" (มองจากบน) แล้วมี **face strip แยก** วางบน tile ที่อยู่ใต้ผนังด้านล่าง
- ต้องมี face set เล็ก ๆ เพิ่ม ~4 tiles: `face-left-end`, `face-mid`, `face-right-end`, `face-single`
- วาดใน layer `Furniture_Above`/overhead เพื่อทับตัวละครถูกต้อง (y-sort)
- ข้อดี: ผนังสูงสมจริง เดินลับหลังผนังได้เหมือน Gather
- ข้อเสีย: ซับซ้อนขึ้น

> **แนะนำ:** เริ่ม A ใน MVP, อัปเกรดเป็น B ตอน polish

## 6. tile เสริมที่ต้องมีนอกเหนือ 47 (ต่อ 1 ธีม)

| กลุ่ม | tiles | หมายเหตุ |
|-------|-------|----------|
| **ประตู (door)** | 2–3 | ช่องเปิดบนผนังแนวนอน/แนวตั้ง (frame + ช่องว่าง) |

ทุกธีมวางตำแหน่ง index เดียวกันเป๊ะ ต่างแค่เนื้อภาพ สลับธีมได้ทันที:

## 8. ตั้งค่าใน Tiled (Terrain / Wang Set)

หลังได้ PNG แล้ว ตั้งใน Tiled:

1. **New Tileset** → เลือก `walls-white.png`, tile size 32×32 (หรือ 64 ถ้าเก็บ @2x) → ได้ `.tsx`
2. เปิด **Tileset editor → Terrain Sets → Add Terrain Set → type = Corner** ตั้งชื่อ `Wall_White`
3. เพิ่ม 1 terrain color (เช่น "wall")
4. **ทาสี terrain ลงทุก tile** ตาม index: ระบายสีมุมของแต่ละ tile ให้ตรงกับ "ด้าน/มุมที่เป็นผนัง" (อ้างตาราง 3×3 ในภาพ)
   - มุมของ tile ที่ควรเป็นผนัง = ทาสี, มุมที่เปิด = เว้นว่าง
5. ใส่ **collision property**: เลือก tile ผนังทั้งหมด → Tile Properties → custom `collides = true` (bool)
6. เซฟ `.tsx` — พร้อมใช้ระบายผนังในแมพด้วย **Terrain Brush** (ต่อกันอัตโนมัติ)

> 💡 ใน Tiled การ "วางตำแหน่ง tile ใน PNG" ไม่ต้องเรียงตามสูตรวิเศษ — เราแค่บอก Tiled ผ่าน Terrain ว่ามุมไหนเป็นผนัง แต่การเรียงตาม index นี้ช่วยให้ตั้งค่าง่าย/ตรวจสอบง่าย และ map ตรงกับ `atlas.json` สำหรับสคริปต์

## ภาคผนวก — ทางเลือกผนังบาง (16-tile edge)

ถ้าต้องการสไตล์ minimal มาก (ผนังบางเป็นเส้น ไม่หนา) ใช้ **16-tile edge set** แทนได้
(อ้างเพื่อนบ้านแนวตรง 4 ทิศ = 2⁴ = 16 แบบ ไม่มีมุมใน) — งานวาดน้อยกว่า แต่มุมจะดู "คม" ไม่มีความหนา
**สำหรับ NexSpace แนะนำ 47-blob** เพราะออฟฟิศมีห้องหลายรูปทรงและต้องการความหนาที่ดู 2.5D ได้
